# 概念学习资料生成器（Concept Learning Generator）

用于把《大数据与人工智能》课程里的抽象概念，转化为一份**可自学、可检验**的学习资料。核心目标是让学习者从"背定义"升级为"真理解"。

## 适用概念范围

覆盖大数据与人工智能课程的核心主题，常见触发词示例：

- **大数据基础**：大数据、分布式计算、Hadoop、HDFS、MapReduce、Spark、数据仓库、ETL、数据湖
- **机器学习**：监督学习、无监督学习、过拟合/欠拟合、特征工程、模型评估、交叉验证、梯度下降
- **深度学习**：神经网络、激活函数、卷积神经网络 CNN、循环神经网络 RNN、Transformer、注意力机制、反向传播
- **AI 应用**：自然语言处理 NLP、计算机视觉 CV、大语言模型 LLM、提示词工程、AI Agent
- **其他**：云计算、虚拟化、流式计算、批处理、推荐系统

> 任何课程中提到的名词都适用，不必局限于上表。

## 输入

用户提供一个概念名（可附带他们卡住的具体疑问，例如"我不懂 MapReduce 里 shuffle 到底干嘛的"）。

## 输出规范

为指定概念生成一篇结构化学习资料，**固定使用以下 6 个部分**，每部分都有明确意图：

### 1. 一句话定义
用 **1 句话**（最好 30 字以内）说清楚它是什么。必须让零基础的人能秒懂，禁止堆术语。

### 2. 核心直觉 / 为什么需要它
回答三个问题：
- 没有它之前，人们是怎么做的？（痛点）
- 它解决了什么根本问题？
- 它的核心思想用一句话怎么概括？

### 3. 生活化类比
用**一个**贴近日常的类比来解释（快递分拣、食堂排队、图书管理员、点外卖等），帮助建立直觉。类比要与真实机制对应，并明确指出"类比中哪个部分对应哪个机制"。

### 4. 工作机制（逐步拆解）
把概念拆成 **3-6 个步骤**，每一步用大白话 + 必要的专业术语标注。涉及流程/架构时，可用文字分步说明或简单示意图（text-diagram）。

### 5. 代码示例
提供一段**可直接运行的最小 Python 示例**（≤30 行），演示该概念。如果该概念难以用代码演示，就给出一个可操作的最小验证思路。
- 代码要有注释，重点行标注"这句在演示 XXX"
- 示例用 Python 3.12 语法，避免复杂依赖（优先标准库或最常用的 numpy）

### 6. 自测练习（3 个）
给 3 道递进式练习检验理解：
- Q1 概念复述（能否用自己的话说）
- Q2 机制辨析（判断对错 / 选择）
- Q3 应用迁移（把这个概念用在一个新场景）
每题后附**参考答案**（放在折叠区或文末"参考答案"小节）。

### 附加：输出到文件（可选）
若用户希望留存，将学习资料写入仓库的 `notes/concepts/<概念名英文或拼音>.md`，文件名用概念名（如 `mapreduce.md`、`transformer.md`）。同时把该概念追加到 `notes/concepts/README.md` 的索引列表中。

## 生成时的写作准则

1. **先共情再讲**：假设读者正在被这个概念难住，先点破"大多数人卡在哪"。
2. **禁止名词轰炸**：一个概念里出现 3 个以上新术语时，必须先解释新术语，再进入正文。
3. **类比优先于定义**：永远先用直觉和类比建立框架，再补严谨定义。
4. **代码必须能跑**：示例代码要在头脑中验证可运行，不写跑不通的半成品。
5. **控制篇幅**：单篇以 400-900 字正文 + 示例代码为佳，不注水。
6. **语言**：默认用中文输出，术语首次出现时标注英文原词。

## 示例输出骨架（MapReduce 节选）

```markdown
## 一句话定义
MapReduce 是一种把"超大计算任务拆成很多小份、并行处理后再合并"的编程模型。

## 核心直觉
没有它：单台电脑算不动海量数据。
它的价值：把一个大活分给成千上万台廉价机器一起干，且自动处理故障。
核心思想：分而治之 —— Map（分/各自算）→ Reduce（合/汇总）。

## 生活类比
像"全校批改期末卷"：先由各班老师(每台机器)批改本班卷子(Map)，再统一汇总成绩(Reduce)。

## 工作机制
1. Input：数据切片...
...
```

## 交付与跟进

- 生成完成后，主动问一句"这部分清楚了吗？还是想让我深入某一步？"以确认学习效果。
- 如果学习者后续提出新概念，用同一套结构继续生成，形成系列笔记。
