Agent、上下文与 Skill 三者之间的关系

把三个概念放到一起看：谁在干活、靠什么信息、按什么规范

1一句话定义

Agent 是"干活的人"，上下文是"他眼前的资料桌"，Skill 是"他手边的标准作业手册"——三者配合，才能稳定地把任务做完。

2核心直觉 / 为什么需要它

  • 没有协作会怎样：只有 Agent 没上下文 → 它瞎猜、记不住前文；只有 Agent 没 Skill → 它乱做、质量不稳定；三者缺一，任务都做不好。
  • 它解决的根本问题：用"上下文"提供记忆与信息，"Skill"提供规范与能力，"Agent"负责调度与决策，三者构成可复用的智能系统。
  • 核心思想（一句话）：上下文是"共享黑板"，Skill 是"能力插件"，Agent 是"调度中枢"。
🤖
Agent
调度中枢：思考、决策、驱动循环
📋
上下文
共享黑板：目标、历史、工具返回
📒
Skill
能力插件：可复用的标准作业 SOP

3生活化类比

像一个项目小组：组长（Agent）盯着共享白板（上下文）上的目标与进度，遇到不会的环节就翻岗位手册（Skill）按步骤做，把产出又写回白板；白板写不下时就归档旧内容。三者配合，小组才能交付。

对应关系：组长=Agent；白板=上下文窗口；岗位手册=Skill；写回白板=Observation 回写上下文；归档=截断/摘要/RAG。

4工作机制（逐步拆解）

  1. 初始化：Agent 启动，在上下文中写入"目标 + 约束"。
  2. 遇子任务：Agent 判断需要某种能力，去 Skill 库里匹配对应 SOP。
  3. 加载 SOP：把 Skill 的步骤与约束读进上下文，作为本次行动的规范。
  4. 执行并写回：按 Skill 执行（可调用工具），过程与结果写入上下文。
  5. 上下文治理：上下文超限时压缩/检索，保证窗口始终在限内。
  6. 循环 / 收尾：回到第 2 步，直到目标达成，输出最终结果。

5代码示例（Python 3.12，可直接运行）

# triad.py —— Agent + 上下文 + Skill 三者协作的最小演示
skills = {"查资料": lambda t: f"找到关于『{t}』的3条要点"}

class Agent:
    def __init__(self, goal: str):
        self.context = {"目标": goal, "笔记": []}   # 上下文 = 共享黑板

    def step(self):
        topic = self.context["目标"]
        result = skills["查资料"](topic)            # 调用 Skill（能力插件）
        self.context["笔记"].append(result)        # 写回上下文（Observation）
        return result

agent = Agent("大模型上下文")
print("Agent 启动，目标：", agent.context["目标"])
print("→ 调用 Skill 得到：", agent.step())         # Skill 写入上下文
print("上下文当前笔记：", agent.context["笔记"])

运行后能看到：Agent 通过 Skill 获取能力，并把结果沉淀进上下文——这正是三者协作的缩影。

6自测练习（3 题）

Q1 概念复述：用一句话概括 Agent、上下文、Skill 各自扮演什么角色。
参考答案
Agent = 调度中枢（决定做什么）；上下文 = 共享黑板（记住信息与结果）；Skill = 能力插件（规定怎么做）。三者分别解决"决策、记忆、规范"三个问题。
Q2 机制辨析：判断正误：只要给 Agent 装上足够多的 Skill，就不需要"上下文"了。
参考答案
错误。Skill 只提供"怎么做"的规范，不保存"当前任务状态"。没有上下文，Agent 无法记住目标、历史与工具返回，多步任务仍会断裂。两者互补，缺一不可。
Q3 应用迁移：设想一个"AI 客服"，分别指出它的 Agent、上下文、Skill 各是什么？
参考答案
Agent = 负责理解用户意图、决定回退还是转人工的调度逻辑；上下文 = 本次会话的全部聊天记录与用户订单信息；Skill = "查订单""退换货流程""安抚话术"等标准作业手册。三者配合完成一次服务。
