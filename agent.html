AI Agent（智能体）

概念英文：AI Agent / Intelligent Agent ｜ 适用场景：大模型应用、自动化任务

1一句话定义

AI Agent 是一个能自己"想办法"、调用工具、一步步把目标做完成的智能程序。

2核心直觉 / 为什么需要它

  • 没有它之前：你每次都要手把手给大模型写提示词、把结果复制出来、再决定下一步做什么——人是"循环驱动器"。
  • 它解决的根本问题：把"思考 → 行动 → 观察"的循环交给程序自动跑，让大模型从一个"问答机"变成能完成多步任务的"执行者"。
  • 核心思想（一句话）：感知—思考—行动—观察的闭环（即 ReAct 范式：Reasoning + Acting）。

3生活化类比

像一位私人助理：你只说一句"帮我订明天去北京的机票"。他会自己查天气（调用工具）、比价（再调用工具）、下单（行动），每一步看到结果后再决定下一步，直到目标达成。

对应关系：你说的话 = 目标；助理的脑子 = 大模型的"思考"；查天气/比价 = 调用工具（Tool）；他看到的返回结果 = 观察（Observation）。

4工作机制（逐步拆解）

  1. 接收目标：用户给出一句话任务（如"查北京天气并判断要不要带伞"）。
  2. 思考（Think）：大模型基于当前情况，决定"下一步该做什么动作"。
  3. 行动（Act）：执行该动作——通常是调用一个外部工具（搜索、计算、读文件、调 API）。
  4. 观察（Observe）：把工具返回的结果写回，作为下一步思考的依据。
  5. 判断终止：若已能回答目标，则输出最终结果；否则回到第 2 步继续循环。
  6. 收尾：把整个过程的结论整理成最终答复返回给用户。

5代码示例（Python 3.12，可直接运行）

# toy_agent.py —— 最小可运行的 Agent 循环（无需联网）
def fake_llm(thought: str, tools: list[str]) -> tuple[str, str | None]:
    # 真实 Agent 这里会调用大模型 API；此处用规则假装"思考"
    if "天气" in thought:
        return "我需要先查天气", "get_weather"
    return "目标已完成，可以答复", None

def get_weather() -> str:
    return "北京 晴 26°C"          # 假装查到了天气

tools = {"get_weather": get_weather}

def run_agent(goal: str, max_steps: int = 5):
    context = f"目标：{goal}\n"
    for step in range(1, max_steps + 1):
        thought, action = fake_llm(context, list(tools))
        print(f"第{step}步 思考：{thought}")
        if action is None:
            print("✅ 完成"); break
        obs = tools[action]()       # 这句在演示"调用工具"
        context += f"→ 工具{action}返回：{obs}\n"
        print(f"  执行 {action} → 观察到：{obs}")

run_agent("明天去北京要带伞吗？")

运行后会看到"思考 → 执行工具 → 观察"的循环；把 fake_llm 换成真正的大模型接口，就成了一个真实 Agent。

6自测练习（3 题）

Q1 概念复述：请用你自己的话（不超过 30 字）说明"AI Agent 和普通聊天机器人最大的区别是什么？"
参考答案
普通聊天机器人只"答"，Agent 会"做"——能自主调用工具、多步推进直到完成任务。
Q2 机制辨析：判断正误：Agent 每执行一次工具调用后，都会把结果丢弃，只保留最初的对话。
参考答案
错误。Agent 会把工具返回（Observation）写回上下文，作为下一步思考的依据；否则无法多步推进。
Q3 应用迁移：如果让你用 Agent 思路做一个"自动整理下载文件夹"的小工具，它会调用哪些"工具"？循环怎么走？
参考答案
工具：列文件、读文件类型/修改时间、移动文件。循环：扫描目录→判断类别→移动→观察结果→是否还有未处理文件→直到清空。本质就是把"人手动归类"自动化成 Think-Act-Observe 循环。
