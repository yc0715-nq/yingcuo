Skill（技能）

概念英文：Skill / Capability ｜ 适用场景：AI Agent 能力封装、可复用工作流

1一句话定义

Skill 是一份写给 AI 的"标准作业流程（SOP）"，让它在特定场景下稳定地做出正确行为。

2核心直觉 / 为什么需要它

  • 没有它之前：每次遇到同类任务都要重新解释"怎么做"，结果时好时坏，全看提示词运气。
  • 它解决的根本问题：把专家经验固化成可复用的指令与步骤，谁（哪个 Agent）来跑都能得到稳定的高质量结果。
  • 核心思想（一句话）：把"怎么做"从人脑搬到文件里，随用随取、可批量复制。

3生活化类比

像餐厅的菜谱：按菜谱的步骤做，不管是谁下厨，都能做出味道差不多的菜。Skill 就是 AI 的"菜谱"——定义了在什么情况下、按什么顺序、调用什么工具完成一道"菜"（任务）。

对应关系：菜谱 = Skill 文件；厨师 = Agent；按步骤炒菜 = 按 SOP 执行；不同菜谱 = 不同 Skill 库。

4工作机制（逐步拆解）

  1. 触发：根据关键词或场景，判断该用哪个 Skill（如"生成学习资料"）。
  2. 加载：读取该 Skill 的说明、约束与推荐步骤。
  3. 执行：按步骤行动，过程中可调用工具或写文件。
  4. 产出：生成结构化结果（如一份 HTML 学习资料）。
  5. 复用：同一份 Skill 可被任意 Agent 多次、跨任务调用，形成"能力积木"。

5代码示例（Python 3.12，可直接运行）

# skill_registry.py —— 注册并调度多个 Skill（像一面菜谱架）
skills: dict[str, callable] = {}

def skill(name: str):                  # 装饰器：把函数登记为一个 Skill
    def wrap(fn: callable) -> callable:
        skills[name] = fn
        return fn
    return wrap

@skill("解释概念")
def explain(concept: str) -> str:
    return f"用生活类比解释『{concept}』"

@skill("写代码")
def code(task: str) -> str:
    return f"为『{task}』生成最小可运行示例"

def dispatch(name: str, *args):
    if name not in skills:
        return "⚠️ 没有这个 Skill"
    return skills[name](*args)        # 按名调用对应 SOP

print(dispatch("解释概念", "注意力机制"))
print(dispatch("写代码", "快速排序"))

运行后能看到：用名字就能"点菜"调用对应能力。把函数体换成真正逻辑，就是生产级 Skill 调度器。

6自测练习（3 题）

Q1 概念复述：Skill 和"一段普通代码"有什么不同？为什么 Agent 需要 Skill 而不是直接写死逻辑？
参考答案
Skill 是"带场景说明与步骤的能力封装"，可被按需触发、跨任务复用；写死逻辑则耦合在某处。Skill 让 Agent 像"翻菜谱"一样灵活组合能力，而不必把所有步骤硬编码。
Q2 机制辨析：判断正误：一个 Skill 只能被一个 Agent 使用，不能共享。
参考答案
错误。Skill 是"能力积木"，设计为可复用；同一份 Skill 可被多个 Agent、多次任务调用，这正是它存在的价值。
Q3 应用迁移：如果让你为"自动写周报"设计一个 Skill，它的步骤（SOP）会包含哪几步？
参考答案
示例：①收集本周 git 提交/文档改动；②按"做了什么/进展/风险"归类；③套用周报模板生成草稿；④交人审阅。把这套步骤固化成 Skill，每周一键复用。
